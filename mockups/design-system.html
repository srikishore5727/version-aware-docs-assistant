01

Color tokens

Use tokens, never raw hex values in components. The token name describes intent, not appearance.

TokenValueUse
--ink#151518Primary text, logo
--ink-2#3F3F46Secondary text, body copy
--muted#71717AMetadata, captions
--line#E7E5E4Borders, dividers
--paper#FBFBFAPage background
--surface#FFFFFFCards, inputs
--accent#4F46E5Primary action, citation
--accent-2#4338CAHover state
--accent-soft#EEF2FFCitation chips, selected
--ok#047857Current doc, confidence
--warn#B45309Not-found, low confidence
Accent appears on roughly 10% of a screen. If it is used for decoration, it is being used incorrectly.

05

Actions

One primary action per screen. Everything else is secondary or a chip.

Primary button

One per view. Indigo fill, white label, 12 px radius. Never used for destructive actions.

Ghost & chip

Ghost for utility actions inside cards. Chips for suggestions and filters.

06

Inputs

Labels sit above the field. Placeholder text is an example, never the label.

Focus ring: 3 px indigo at 12% opacity, plus a solid indigo border. Hover is a grey border shift only.

07

Badges

Short, factual, and never decorative. Each one encodes a single property.

API reference v3 Current Not relevant enough Answer High confidence Internal beta

Grey = document type. Indigo outline = version. Green = freshness or confidence. Amber = caution. Never encode the same meaning with two colours.

08

Cards

Four card types carry the product: answer, source, notice, and skeleton.

Answer card

Answer High confidence 3 sources · 1.2 s

No. In v3, user_name was renamed to display_name. Requests that still send the old field return 422.12

The answer never renders without at least one citation chip or the not-found state.

Source card

API reference v3 Current 0.92

Create user

display_name (string, required) — replaces user_name, which was removed in v3.

Request body · Updated 12 Oct 2026Open in docs ↗

Type icon, type tag, version, freshness badge, relevance meter, date, and an escape hatch to the full document.

Notice card

No reliable answer in the docs

The indexed documentation does not cover Okta SSO. Rather than guess, VADA stops here.

Try rephrasing, widen the version filter, or browse the authentication section.

Amber, left-accented, never red. A documentation gap is a caution, not an error.

Skeleton

Shimmer runs for a maximum of 1.5 s. After that, show the not-found or error state.

09

States

Every interactive component defines five states before it is considered complete.

StateRule
Rest1 px --line border, no shadow
HoverBorder shifts to #D4D4D8; cards lift 1 px
Focus2 px indigo ring, 2 px offset — always visible
ActiveButton translates 1 px down; no colour change
DisabledGrey fill, muted label, no shadow, cursor: not-allowed
Loading is a sixth state for any data surface: skeleton for under 1.5 s, then a labelled error.
10

Accessibility

Checklist applied to every component before merge.

  • Semantics: real button, a, label, and heading levels. No clickable divs.
  • Labels: every input has a visible label or an aria-label.
  • Live regions: answer and error containers use aria-live="polite".
  • Contrast: 4.5:1 for text, 3:1 for large text and UI borders.
  • Motion: honour prefers-reduced-motion; the skeleton stops shimmering.
  • Targets: 44 × 44 px minimum on touch screens.
